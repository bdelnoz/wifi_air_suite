# Why wifi_air_suite exists

Version: **v3.0.0**

`wifi_air_suite` is built around separation of concerns and predictable artifacts.

## Capture should remain capture

A capture command must not unexpectedly start `aircrack-ng`, a cracking workflow or an active wireless action. `--capture`, `--check`, `--crack` and authorized lab actions therefore remain distinct business actions behind explicit CLI gates.

## Long captures need bounded storage behavior

Interval captures can run for hours. The terminal recording generated by the PTY logging path can become much larger than the small control log, even when the useful CAP/CSV data is already stored separately.

v3.0.0 retains the explicit no-persistent-log mode:

```text
--nolog
--no-log
```

This lets the operator keep the data used for later analysis while suppressing persistent terminal/action logs for that invocation.

The design preserves:

- CAP and CSV capture artifacts;
- filtering and exclusion logic;
- OUI enrichment;
- filtered Markdown generation;
- per-interval post-processing;
- live airodump display when the spinner is disabled;
- the default logging behavior when `--nolog` is not requested.

## Targeted BSSID captures should not waste time hopping channels

When the operator already knows both the BSSID and its channel, channel hopping adds avoidable dwell time on unrelated frequencies. v3.0.0 retains `--channel N` for BSSID-targeted capture while keeping the existing multi-channel default unchanged.

The option is deliberately constrained to `--capture` with `--bssid`, making the intent explicit and preventing ambiguous use in unrelated actions.

## Manufacturer data should be refreshable without manual file replacement

OUI assignments change over time. v3.0.0 retains `--update-oui` so manufacturer enrichment can be refreshed from the IEEE Registration Authority public MA-L/OUI listing without manually downloading and reformatting a source file.

The updater stages and validates the download before replacement and keeps `myinfo/oui.txt.bak`, so a broken or partial response does not destroy a working local database.

## Runtime data belongs outside the source tree

Generated results are grouped below `.results/` instead of being mixed with source/documentation files. This keeps the repository clean and allows `.gitignore` to exclude high-volume capture artifacts in one place.

## Explicitness over hidden behavior

Real operational actions use `--exec`. Simulations use `--simulate`. Active behavior is never implied by a passive capture request.

That contract makes the script easier to inspect, test and operate repeatedly without hidden side effects.
## A major baseline should be boring to upgrade to

v3.0.0 is intentionally a consolidation release. The validated v2.1.4 behavior is retained while the script, examples, specifications, installation guide, changelog, README and Product Guide are aligned on one documented baseline. The major version marks a packaging/documentation boundary, not a hidden change to capture semantics.
